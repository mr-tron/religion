# Компас мировоззрений

Статический сайт без сборки, сервера приложений и внешних зависимостей. Откройте `index.html` в браузере. Для локального HTTP-просмотра: `python3 -m http.server 8000`.

Для GitHub Pages: в репозитории [mr-tron/religion](https://github.com/mr-tron/religion) откройте **Settings → Pages**, выберите **Deploy from a branch**, ветку **main** и папку **/(root)**. Сайт будет доступен по адресу `https://mr-tron.github.io/religion/` после публикации. Относительные пути уже подходят для проектного сайта; сборка не нужна.

## Устройство

- `questions.js` — только вопросы и их уникальные идентификаторы.
- `religions.js` — исходные семейства и учения; `catalog.js` — подключённые записи из проверенных партий. Связь с вопросами идёт через идентификаторы признаков. Эти файлы загружаются без `fetch`, поэтому сайт работает даже при открытии `index.html` с диска.
- `engine.js` — проверка каталога, пересчёт близости и выбор следующего вопроса по ожидаемому снижению неопределённости. Вопросы о конкретных традициях задаются после общих ответов, указывающих на соответствующее направление. Не зависит от браузера.
- `app.js` — интерфейс, история ответов и отображение результатов. После 10 ответов показывается предварительный результат; по желанию опрос продолжается блоками по пять вопросов.
- `styles.css` — оформление и адаптивная вёрстка.
- `religions.txt` — исходный список кандидатов; метод и ограничения описаны в `religions_review.md`. Проверенные записи перенесены в партии каталога.
- `AGENT_BATCH_PROMPT.md` — единый промпт для проверки партий по 15–20 записей из `religions.txt`.
- `catalog_batches/` — отдельные результаты проверки. Записи со статусом `keep` включены в `catalog.js`; `alias` и `review` в опрос не добавлены.
- `scripts/validate-batches.js` проверяет партии против исходного списка и текущих признаков; `scripts/build-catalog-report.js` создаёт сводку синонимов, спорных записей и предложенных вопросов в `catalog_batches/REVIEW.md`.
- `scripts/build-live-catalog.js` пересоздаёт `catalog.js` после редакции партий. Сгенерированный файл хранится рядом с сайтом, поэтому публикация на GitHub Pages не требует сборки.
- `scripts/audit-profiles.js` показывает число признаков у каждой сравниваемой записи и список профилей с менее чем тремя признаками. После правки партии запустите `node scripts/validate-batches.js`, затем `node scripts/build-live-catalog.js` и `node scripts/audit-profiles.js`.

Каталог содержит 1546 направлений: 123 исходных и 1423 из проверенных партий. В подборе участвуют профили минимум с тремя подтверждёнными признаками; остальные доступны в каталоге. Актуальное покрытие показывает `node scripts/audit-profiles.js`. Ход проверки и следующий диапазон записаны в [журнале обогащения](catalog_batches/FEATURE_REVIEW.md).

## Как расширять каталог

1. Добавьте запись в `rows` внутри `religions.js`: `семейство|Название|Краткое описание|+признак -другой_признак`.
2. Общие признаки семейства задаются в `families` того же файла. Признаки записи переопределяют семейство. Отсутствующий признак означает «неизвестно или варьируется», а не «нет».
3. Для нового различия добавьте вопрос с уникальным `id` в `questions.js` и назначьте этот признак подходящим записям в `religions.js`. Алгоритм подхватит его сам.
4. Проверьте изменения командой `node --test tests/*.test.js` (Node.js 18+).

`+` означает типичный ответ «Да» (вероятность 0,88), `-` — «Нет» (0,12), `?` — отсутствие различающей информации (0,5). Это редакционная модель, а не утверждение о каждом последователе. Для участия в подборе требуется минимум три проверенных признака; записи с более короткими профилями остаются в каталоге для дальнейшего исследования. Если два учения имеют одинаковые профили, опрос не может различить их; при развитии базы добавляйте содержательные вопросы, а не искусственные метки.

## Ограничения

Каталог содержит как широкие семейства, так и узкие школы. Их границы спорны, а взгляды внутри них разнообразны. Результат показывает близость к упрощённым профилям и не определяет религиозную принадлежность человека. Источники для структуры каталога указаны в интерфейсе; отдельные профили требуют дальнейшей проверки и уточнения. Ответы не отправляются никуда и не сохраняются после обновления страницы.
