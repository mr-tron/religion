# Промпт для обработки партии религий

Ты работаешь в корне репозитория статического классификатора мировоззрений. Тебе назначены **ровно N последовательных записей** из `religions.txt` с индексами A–B (индексы считаются по строкам данных, без пустых строк и комментариев). Прочитай `religions_review.md`, `questions.js`, `religions.js` и `engine.js` перед началом. Обрабатывай только свою партию; соседние записи не меняй.

Цель — подготовить проверяемые данные для переноса в опросник. Для **каждой** записи:

1. Открой ссылку из `religions.txt`; при неоднозначности найди второй надёжный источник. Исторические традиции, локальные практики, организации и узкие ветви допустимы. Не выкидывай запись только за редкость или отсутствие нынешних последователей.
2. Определи, отдельная ли это традиция/ветвь, или подтверждённый синоним другой записи в `religions.txt` **либо уже существующей записи в `religions.js`**. Язык и транслитерация названия не делают то же учение новым. Сходное написание и родство учений не доказывают тождество. Для синонима укажи каноническое название и ссылку, подтверждающую связь.
3. Укажи ближайшее семейство из `religions.js` либо поставь `family: null` и предложи новое семейство в `notes`. Для исторических традиций используй уже предложенные имена там, где они подходят: `ancient_neareastern`, `ancient_american`, `ancient_european`, `ancient_anatolian`, `ancient_caucasian`; для живых локальных европейских практик — `european_folk`. Не создавай новое имя для того же семейства. Дай короткое нейтральное описание на русском и, если подтверждено, родительское направление. Не приписывай каждому последователю одинаковые убеждения.
4. Соотнеси только **проверенные** отличительные признаки с ID из `questions.js`: `+id` для типичного «Да», `-id` для типичного «Нет». Поставь `inheritFamilyProfile: false`: профиль семейства содержит обобщения, которые нельзя автоматически приписывать новой узкой традиции. При недостатке данных оставь профиль пустым. Для важного нового различия предложи вопрос с формулировкой «Да/Нет/Иное» и объясни, какие записи он разделит. Не придумывай вопросы только ради уникальности профиля.
5. Добавь источники конкретно к своей записи. Если ссылка ведёт на статью о народе или организации и не подтверждает само учение, укажи эту неопределённость.

Запиши результат **только** в свой файл `catalog_batches/batch_AAAA_BBBB.json`. Не редактируй `app.js`, `engine.js`, `questions.js`, `religions.js`, `religions.txt`, `index.html` или файлы других партий. Создай папку при необходимости. JSON должен иметь вид:

```json
{
  "range": [1, 15],
  "entries": [
    {
      "sourceIndex": 1,
      "sourceName": "Name in religions.txt",
      "decision": "keep",
      "canonicalName": "Нейтральное название",
      "family": "indigenous",
      "inheritFamilyProfile": false,
      "parent": null,
      "description": "Короткое описание на русском.",
      "profile": "+nature_spirits +ancestors",
      "proposedQuestions": [],
      "sources": ["https://example.org/source"],
      "notes": "Оговорки и степень уверенности."
    }
  ]
}
```

Для подтверждённого синонима поставь `decision: "alias"`, `canonicalName` равным сохранённой записи и объясни решение в `notes`; для неразрешённой неоднозначности — `decision: "review"`. Не оставляй записи без решения. Число элементов в `entries` должно точно равняться размеру партии, `sourceIndex` и `sourceName` должны совпадать с `religions.txt`. Прежде чем закончить, проверь синтаксис JSON и все индексы. В ответе сообщи путь файла, число `keep`/`alias`/`review` и важные предложения по новым вопросам.

## Повторный проход: обогащение признаков

Если партия уже проверена, сохраняй решения `keep`/`alias`/`review` и расширяй профили `keep` по дополнительным источникам. Для каждого добавления запиши основание в `notes` и URL в `sources`. Отдельно проверяй смысл формулировки вопроса: упоминание медиума не обязательно доказывает одержимость, изображения — ношение масок, а созерцание — медитацию. Не дополняй профиль ради числового порога. Если источник подтверждает только часть региональной или исторической традиции, явно обозначь границы.

Назначенный диапазон может пересекать несколько файлов партий. Меняй только свои записи и перечитывай файл перед точечной правкой, чтобы сохранить параллельные изменения. Признаки из `verifiedQuestionLinks` в `scripts/build-live-catalog.js` не дублируй: сообщи новые подтверждённые индексы для обновления генератора. В конце выполни `node scripts/validate-batches.js` и сообщи число расширенных профилей, добавленных признаков и ограничения источников.
